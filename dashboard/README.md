# dashboard/

Periodic export of dashboard `al9xz4` ("Fork the Internet — Stage 1: Reachability")
as it exists in Grafana Cloud, for version control and disaster recovery. This is a
snapshot, not an auto-sync -- Grafana Cloud remains the live editing surface; this
file is committed by hand after a work session, whenever the dashboard has changed
meaningfully.

## Why this exists

Every other decision in this project lives in the repo, not only in a hosted tool
(the "Git for reality" pitch in the project briefing). Until now the dashboard was
the one exception -- it existed only in Grafana Cloud with no local backup and no
diff history. This file closes that gap.

## `al9xz4.json`

`GET /apis/dashboard.grafana.app/v2beta1/namespaces/stacks-640146/dashboards/al9xz4`,
with the volatile, server-generated fields stripped before committing
(`resourceVersion`, `generation`, `creationTimestamp`, `uid`, `createdBy`/
`updatedBy`/`updatedTimestamp`, the `status` block, the `deprecatedInternalID`
label). Kept: `apiVersion`, `kind`, `metadata.name`, the folder annotation, and the
full `spec` (panels, layout, variables, conditional rendering). Pretty-printed for
readability and diffability.

**Must be re-exported via the v2beta1 API, not the classic dashboard tools**
(`get_dashboard_by_uid`/`update_dashboard` in the MCP Grafana tooling stay v1-shaped
and silently drop `conditionalRendering` -- see the project briefing's Step 5
re-entry point and `docs/decisions/gate2-globe-panel.md`). A re-import from this file
would need the same v2beta1 endpoint, not a v1 dashboard import.

This file is **not wired into the build** and not auto-regenerated by
`scripts/build_graph.py` or the weekly GitHub Action -- re-export it manually after
dashboard changes worth preserving.
